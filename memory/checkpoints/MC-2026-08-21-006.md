# MEMORY CHECKPOINT — MC-2026-08-21-006

## Etapa
Definición de modelos, relaciones, campos, validaciones y captura para Reproducción y Lactancia.

## Estado
**CONCLUIDO — DISEÑO PUBLICADO. NO IMPLEMENTADO.**

## Decisión arquitectónica
No duplicar información que ya pertenece a `Animal`. El modelo `Animal` conserva identidad, finca, sexo, nacimiento y genealogía. Los nuevos modelos deben representar hechos históricos y mediciones específicas.

Cadena:

`Animal → EventoReproductivo → CriaNacimiento → Lactacion → ControlLeche → Motor de Métricas`

## Modelos propuestos

### EventoReproductivo
Registra celo, servicio, diagnóstico de gestación, aborto/pérdida, parto, destete y otros eventos reproductivos.

### CriaNacimiento
Conserva el hecho histórico del nacimiento y enlaza con la cría cuando existe como `Animal`, sin sustituir la genealogía.

### Lactacion
Representa una lactación individual de una hembra, con número, fechas, estado y parto asociado.

### ControlLeche
Representa una medición individual de leche con fecha/hora, cantidad, unidad, turno, método y calidad opcional.

## Reglas

- Todo dato debe quedar asociado a animal y finca cuando corresponda.
- Fechas efectivas y fechas de registro deben poder diferenciarse.
- Unidades obligatorias para magnitudes.
- Fuente del dato y responsable deben ser trazables.
- Validaciones de sexo, especie, finca, fechas y duplicidad.
- No guardar métricas agregadas como hechos si pueden derivarse del historial.
- Las fórmulas pertenecen al Motor de Métricas, no a los modelos de captura.

## Captura
Los formularios deben ser contextuales: finca → animal → tipo de evento → datos específicos → fuente → observación. Para leche: finca → hembra → lactación → medición → unidad → turno/método → calidad opcional → fuente.
